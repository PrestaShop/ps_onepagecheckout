# Translations (`ps_onepagecheckout`)

This document describes how to **add**, **package**, and **use** translations for the module under PrestaShop 9 (Symfony / XLIFF system).

## Translation domains

| Context | Recommended domain | Usage example |
|---------|-------------------|---------------|
| Module-specific strings (BO) | `Modules.Psonepagecheckout.Admin` | `displayName`, tab labels, module texts |
| PrestaShop core strings (BO) | `Admin.Actions`, `Admin.Design.Feature`, `Admin.Notifications.*`, etc. | Buttons, titles, alerts already translated by the core |
| Module-specific strings (FO) | `Modules.Psonepagecheckout.Shop` | Checkout page labels, error messages, UI strings |

The module entry point uses `Modules.Psonepagecheckout.Admin` (see `ps_onepagecheckout.php`). Configuration screens often reuse `Admin.*` domains to stay aligned with the back office.

> **Consistency**: use the same source string (in English) everywhere for a given phrase, and the same domain so the XLF files match.

## Where to place files

Translations packaged with the module live under:

```text
translations/
  en-US/
    ModulesPsonepagecheckoutAdmin.en-US.xlf
    ModulesPsonepagecheckoutShop.en-US.xlf
  fr-FR/
    ModulesPsonepagecheckoutAdmin.fr-FR.xlf
    ModulesPsonepagecheckoutShop.fr-FR.xlf
  pl-PL/
    ModulesPsonepagecheckoutAdmin.pl-PL.xlf
    ModulesPsonepagecheckoutShop.pl-PL.xlf
```

File names generated by the PrestaShop console may vary slightly; what matters is the **domain** inside the XLF and the **locale** (`fr-FR`, `en-US`, …).

## Creating or updating translations

### Option A — From the back office (recommended for content)

1. Install the module on a PrestaShop 9 shop.
2. Go to **International > Translations**.
3. Translate the module strings (domains `Modules.Psonepagecheckout.Admin` and `Modules.Psonepagecheckout.Shop`).

### Option B — Export from the console (to ship XLF files in the repository)

From the root of **PrestaShop** (not just the module):

```bash
php bin/console prestashop:translation:export-module ps_onepagecheckout fr-FR
```

Without a locale, the command can export all available languages (see the [official documentation](https://devdocs.prestashop-project.org/9/development/components/console/prestashop-translation-export-module/)).

Then unzip / copy the generated `translations/` folder into the module root in the repository.

## Using translations in code

### PHP — `Module` class

```php
$this->trans('One-page checkout', [], 'Modules.Psonepagecheckout.Admin');
```

With an explicit locale (e.g. multilingual tab names):

```php
$this->trans('Checkout', [], 'Modules.Psonepagecheckout.Admin', $lang['locale']);
```

### PHP — outside `Module` (e.g. `BackOfficeConfigurationForm`)

Use the context translator:

```php
$translator = \Context::getContext()->getTranslator();
$translator->trans('My string', [], 'Modules.Psonepagecheckout.Admin');
```

The private `trans()` helper in `BackOfficeConfigurationForm` does the same; its default domain must stay aligned with `Modules.Psonepagecheckout.Admin` for module strings.

### Twig

BO templates (`views/templates/admin/*.html.twig`) generally receive **pre-translated strings** from PHP (variables passed at render time). You can also translate directly in Twig:

```twig
{{ 'My string'|trans({}, 'Modules.Psonepagecheckout.Admin') }}
```

### Smarty (legacy)

- **With Symfony domain** (recommended if the theme / context supports it):

```smarty
{l s='My string' d='Modules.Psonepagecheckout.Admin'}
```

- **Legacy module style** (`mod=`): uses the module's legacy PHP files, **not** the Symfony XLF files of the same name. Prefer the `d=` domain to stay consistent with this repository.

## JavaScript strings

The module does not yet ship a dedicated JS translation catalogue. For messages displayed in JS:

- either pass **pre-translated** labels from PHP (`Media::addJsDef`, configuration exposed to the front end),
- or expose a small translations object built on the PHP side with `$translator->trans(...)`.

## Best practices

- **Source language**: write strings in English in the code.
- **No duplicates**: do not duplicate the same phrase with minor variants (spaces, punctuation) — one entry per meaning.
- After adding new strings to the module, **re-export** or complete the XLF files for each targeted locale.
- `translations/*.php` files auto-generated by PrestaShop may exist locally but are not the primary target for PS 9; the **XLF** format is the one to version for distribution.
